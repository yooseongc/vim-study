# Vim Field Guide

실제 Vim으로 상황을 해결하는 한국어 실전 훈련장. 배포 경로는 https://yooseongc.github.io/vim-study/ 입니다.

## 실행

Node.js 22 이상에서:

```sh
npm ci
npm run dev
npm test
npm run build
```

개발 서버가 출력하는 `/vim-study/` 주소로 접속합니다. `file://`에서는 동작하지 않습니다. 산출물은 `dist/`입니다. 외부 CDN 없이 Vim 바이너리를 함께 배포합니다.

## 구현 범위

- `#quickfix-workshop`은 한 파일의 검색 위치, 두 파일의 편집과 모두 저장, 설명 파일을 보존하는 독립 문제입니다. 긴 검색 명령을 의미별로 안내하되 연속 입력을 허용합니다. 목록 위치와 미저장 버퍼 수를 실제 Vim에서 읽고, 편집 중인 모든 대상 버퍼·저장된 파일·보존 파일을 구분해 검사합니다. `:copen`과 `:cclose`, `:cprevious`도 연습할 수 있습니다. `node scripts/quickfix-workshop.mjs`는 실제 목록과 파일 이동, 숨은 미저장 변경, 현재 파일만 저장한 경우, 보호 파일 복구, 세 문제와 다섯 화면 크기를 검증합니다.

- `#block-workshop`의 **같은 열을 골라 함께 편집하기**는 선택 방식 비교 → 블록 I 입력 → 번호 열 삭제 → 독립 조합 문제입니다. 실제 선택 행·열을 표시하고, 첫 줄 입력이 Esc 뒤 다른 줄에도 적용되는 시점을 설명합니다. 고정 폭 영문 예시를 사용하며 탭·한글·길이가 다른 줄의 선택까지 일반화하지 않습니다. `node scripts/block-workshop.mjs`로 실제 선택·취소·입력 적용·undo/redo·보호할 줄·저장·다섯 화면 크기·기록 미생성을 검사합니다.

- 첫 화면과 `#workshop`은 새 학습 방식의 첫 단원 **한 번 바꾸고, 다시 쓰기**입니다. 개념 카드와 편집 전후 미리보기 → 실제 Vim에서 이어 입력하는 안내 문제 → 보존할 검색 결과를 건너뛰는 독립 문제로 연결됩니다. 완료 뒤에는 `#range-workshop`의 **범위를 고르고, 확인하며 바꾸기**, `#register-workshop`의 **복사한 내용을 지키며 편집하기**, `#macro-workshop`의 **여러 동작을 묶고, 확인하며 반복하기**, `#navigation-workshop`의 **멀리 이동하고, 다시 돌아오기**, `#block-workshop`의 **같은 열을 골라 함께 편집하기**, `#quickfix-workshop`의 **검색 목록을 따라 편집하기**로 이어집니다. 기존 단원은 목차와 각 해시 주소로 접근할 수 있습니다. 새 화면은 일곱 단원에 적용했으며 기존 과정 전체를 재설계한 상태는 아닙니다.
- 새 치환 단원은 한 줄의 첫 항목과 g 옵션 비교, 1~2번 줄 범위, 전체 줄에서 c 옵션으로 확인, 독립 문제의 네 문제입니다. 각 문제의 결과를 저장한 뒤 개념을 확인합니다. 실행 전 미리보기는 현재 줄·1~2번 줄·전체 줄과 g의 여섯 조합을 비교하며, 고정된 영문 예시만 처리합니다. Vim 정규식 시뮬레이터는 아닙니다.
- 새 단원은 `PracticeRun`의 편집기·설정·초기화·저장 판정·힌트를 공유합니다. 치환·레지스터·매크로·이동·블록·quickfix는 여러 문제의 진행·개념 확인·완료 화면도 `SegmentWorkshop`으로 공유합니다. 학습 내용과 실제 상태별 안내는 각 단원의 데이터에 둡니다. 긴 치환 명령은 작은 화면에서 안내 높이를 늘려 마지막 옵션과 Enter까지 보이게 합니다.
- 새 레지스터 단원은 기본 보관함의 복사·삭제 비교와 숫자 0 복구, 이름 붙인 a, 밑줄 레지스터로 버리기, 독립 과제의 네 문제입니다. 기본·0·a의 실제 내용을 편집기 위에서 확인할 수 있습니다. 첫 문제는 잘못 붙인 줄을 u로 복구한 뒤 복사 내용을 꺼내는 흐름이며, undo가 파일과 레지스터를 똑같이 복원하지 않는다는 점도 설명합니다. 연습은 결과와 저장을 검사하며 특정 키 순서를 강제하지 않습니다.
- 새 매크로 단원은 짧은 녹화와 한 번 재생, 예외 줄 건너뛰기와 실수 복구, 독립 과제의 세 문제입니다. 점과 매크로의 끝 위치를 비교하고, 실제 녹화 상태와 a의 내용을 표시합니다. Esc는 읽기 쉬운 표기로 보여줍니다. 새 단원의 공통 완료 판정은 내용·저장·일반 모드 외에 녹화 종료도 확인합니다. 결과가 같아도 녹화 중에는 넘어가지 않습니다.
- 새 이동 단원은 mark의 줄·칸 복귀, 점프 기록 왕복, 돌아와 편집하는 독립 과제의 세 문제입니다. 현재 행·열과 mark a, 실제 점프 기록 수를 표시합니다. 들여쓴 영문 예시에서 작은따옴표와 백틱의 차이를 비교하며, mark a가 레지스터 a와 별개인 점과 Ctrl+o가 편집 취소가 아닌 점을 설명합니다. 이동은 파일을 바꾸지 않으므로 각 문제에서 실제 편집·저장까지 마무리합니다. 완료 판정은 결과와 저장을 기준으로 합니다.
- 안내 문제는 다섯 결과 지점(검색, 첫 변경, 다음 위치, 반복, 저장)을 실제 Vim 상태로 확인합니다. 키마다 다음 버튼을 누르지 않으며 `ciw`를 이어 입력하거나 중간 상태를 빠르게 지나가도 결과를 받아들입니다. undo로 되돌리면 해당 상태의 안내로 돌아갑니다. F2는 점진적 힌트, Ctrl+Enter는 저장 확인 후 마무리, Ctrl+Shift+F는 안내 영역으로 포커스 이동입니다. 내용 점검은 요청 뒤의 스냅샷을 사용하며 수정이 시작되면 지난 진단을 지웁니다.
- 새 연습은 기록을 저장하지 않습니다. 초기화는 현재 문제만 되돌리고, 완료 화면에서는 Vim Worker를 정리합니다. `:w`는 해당 연습 세션의 파일 저장입니다. 글꼴 설정은 기존 설정을 사용합니다. 캔버스와 함께 확인할 수 있는 읽기 전용 텍스트 표현을 제공합니다.
- `node scripts/workshop.mjs`는 키보드만으로 안내 문제 진행, 연속 입력, 힌트 포커스, undo/redo, 보존할 줄의 정확한 피드백, 문제 단위 초기화, 저장 조건, Worker 정리, 기록 미생성, 여섯 화면 크기에서 설명·편집기·진행 버튼의 동시 노출을 검증합니다. 작은 화면 검사는 데스크톱 브라우저의 뷰포트 검사이며 실제 모바일 OS 키보드 동작을 보장하지 않습니다.
- `node scripts/range-workshop.mjs`는 미리보기 여섯 조합을 실제 Vim과 비교하고 네 문제, y/n/q 확인과 undo 복구, 잘못 바꾼 설명 줄, 저장 조건과 개념 질문, 기록 미생성, 화면 크기 변경 중 확인 모드 유지·캔버스 픽셀 보존을 검사합니다. 크기 변경은 어댑터가 단독 관리하며 vim-wasm의 지연 resize가 같은 캔버스를 다시 지우지 않도록 합니다.
- `node scripts/register-workshop.mjs`는 실제 기본·0·a 보관함, 삭제 후 잘못 붙이기와 u 복구, 이름 붙인 복사, 버리기 삭제, 저장·개념 확인, 독립 과제와 현재 문제 재시작, 기록 미생성, 다섯 화면 크기와 미저장 이동 경고를 검증합니다.
- `node scripts/macro-workshop.mjs`는 실제 녹화와 기존 a 덮어쓰기, 점과 @a의 커서 차이, @@ 재생, 예외 줄 복구와 a 보존, 녹화 종료·저장 판정, 세 문제, 다섯 화면 크기와 기록 미생성을 검증합니다.
- `node scripts/navigation-workshop.mjs`는 mark와 register a의 분리, 작은따옴표·백틱의 실제 열 위치, Ctrl+o/Ctrl+i의 왕복과 편집 보존, 입력 모드 유지 안내, 보존할 줄의 오답·복구, 세 문제의 저장, 다섯 화면 크기와 기록 미생성을 검증합니다.

- `#basics`의 **기억을 정리하는 첫 편집**은 M2 안내 단원입니다. Esc → i → 텍스트 입력 → Esc → u → Ctrl+r → 콜론 → w → Enter를 아홉 화면으로 나누고, 각 키의 뜻과 예상 결과를 설명합니다. 실제 Vim의 모드·버퍼·명령줄·저장 이벤트로 단계를 검증하며, 확인 전에는 다음 단계로 넘어가지 않습니다.
- 단원 마지막에는 개념 확인 질문 세 개와 별도의 새 파일에서 직접 편집·저장하는 연습을 제공합니다. 완료 기록과 마지막 저장 내용은 `vim-field-guide:basics:v1`에 저장합니다. 안내 단원은 다시 방문하면 초기 파일부터 시작합니다. 중간 단계/undo 이력 복원은 하지 않습니다. 기존 여섯 미션의 데이터는 유지됩니다.
- 안내 UI는 사이트에 포함된 Noto Sans KR을 사용합니다. 본문은 16px, 보조 문구는 13–14px로 표시하고 대비를 높였습니다. 넓은 화면에서는 설명과 Vim을 나란히 표시하며, 좁은 화면은 세로 배치와 가로 스크롤 단원 목록을 사용합니다. 편집기 높이는 화면 높이에 반응하며 **편집기 확대**로 학습 설명을 잠시 접을 수 있습니다. ResizeObserver로 실제 Vim 캔버스 해상도와 편집 영역을 함께 갱신합니다.
- vim-wasm 0.0.13에 포함된 실제 Vim 8.2.0055. 모방한 키 바인딩이 아닌 Vim의 검색, text object, 레지스터, 매크로, 버퍼, 분할을 사용합니다.
- 설정 포트 수정, 문자열 편집, 점 반복, 범위 치환, 매크로 변환, 두 버퍼 동기화의 여섯 미션.
- 단계별 힌트와 완료 후 복습. 정해진 키 순서를 강제하지 않으며 저장된 파일 내용을 검증합니다. 부수적인 변경도 검출합니다.
- 편집기 아래 **편집기 설정**에서 Mono 폰트와 12–28px 크기를 선택합니다. 미리보기와 실제 Vim에 적용하고 다음 방문에도 보관합니다. 기본값은 시스템 Mono 16px입니다. JetBrains Mono, Fira Code, Source Code Pro, IBM Plex Mono, Inconsolata는 사이트에 포함되어 설치 없이 사용합니다. Cascadia Code/Mono, Consolas, Menlo, Monaco, Courier New는 기기에 설치된 것을 사용하며 없으면 시스템 Mono로 대체합니다. 한글은 기기의 대체 글꼴을 사용합니다. 영문 일반·굵은 글꼴을 로드한 뒤 Vim의 글자 폭을 계산합니다.
- 미션별 지정 파일은 `:w` 시 localStorage에 보관합니다. 미저장 변경은 이동·종료 시 경고합니다. `:wa`로 여러 버퍼를 저장할 수 있습니다.
- 완료 기록은 로컬 브라우저에만 보관합니다. 계정 동기화는 없습니다. 자유 작업 공간에서는 지원하는 이름의 텍스트 파일을 새로 만들어 보관할 수 있습니다.
- `/vim-study/` 범위의 coi-serviceworker로 GitHub Pages에서 cross-origin isolation을 구성합니다. 최초 접속 시 한 번 새로고침될 수 있습니다.

## 학습 원칙과 다음 과정

현재 개발 마일스톤 M1–M6의 학습 콘텐츠와 기능을 구현했습니다. 이는 수업 제공 범위의 완료이며 사용자의 숙련도나 실제 서버 작업 능력을 인증한다는 뜻은 아닙니다.

| 단계 | 제공 범위 |
| --- | --- |
| M1 | React, 실제 Vim WASM, 반응형, 폰트 설정 |
| M2 | 모드·입력·undo/redo·저장의 9단계 안내 |
| M3 | 동작과 범위를 조합하는 18단계 안내 |
| M4 | 실제 상태 진단과 독립·변형 과제 |
| M5 | 파일 보관, 버퍼, 창 분할·이동, 다운로드 |
| M6 | 점·치환·레지스터·매크로·mark/jumplist·블록·quickfix·argdo·global, 로컬 전이 실습 |

M6 후반의 새 안내 단원은 다음 순서로 연결됩니다. 모두 한 동작씩 실행하는 안내, 이해 확인 3문제, 다른 내용의 독립 과제를 제공합니다. 완료·복습 기록은 저장하지 않습니다. 독립 과제는 키 순서를 강제하지 않고 결과와 저장 상태를 검사합니다.

| 주소 | 단원 | 안내 단계 |
| --- | --- | --- |
| `#registers` | 이름 붙인 레지스터, 삭제와 복사 보존, black hole | 20 |
| `#macros` | 녹화·중지·한 번 실행·재실행·undo/redo | 17 |
| `#navigation` | mark, 작은따옴표와 백틱, Ctrl+o/Ctrl+i | 20 |
| `#block` | Ctrl+v, 직사각형 선택, I 입력과 Esc 적용 | 12 |
| `#quickfix` | vimgrep, 다음·이전 검색 결과, 두 파일 저장 | 27 |
| `#batch` | args, argdo 치환, update, 첫·마지막 파일 확인 | 20 |
| `#global` | 줄 시작 패턴, 조건에 맞는 줄 삭제 | 10 |
| `#local` | 다운로드 실습, 여러 파일·매크로·로그 편집, 외부 필터, 셸 왕복, 읽기 전용 복구, SSH 안내 | 6개 과정 |

단원 순서는 `lessons/catalog.js`, 공통 단계 구성은 `lessons/builders.js`에서 관리합니다. Vim 스냅샷에는 이름 붙인 레지스터·녹화 여부·mark·선택 시작점·quickfix·arglist·저장된 파일 내용도 포함합니다. 여러 파일 과제는 현재 버퍼뿐 아니라 다른 파일의 디스크 내용과 전체 미저장 버퍼 수, 보존할 파일까지 검사합니다. Vim 사전의 키 순서는 판정에 영향을 주지 않습니다. 여러 파일 저장 후 출력 확인을 기다리는 모드도 안내합니다.

로컬 과정은 `vim-study-lab.zip`의 여섯 파일을 실제 Vim에서 편집합니다. Bash의 `verify.sh` 또는 사이트의 파일 선택 검사기로 결과를 비교할 수 있습니다. 선택한 파일은 브라우저에서만 읽고 전송·저장하지 않습니다. ZIP은 빌드 때 `scripts/lab-assets.mjs`로 생성하며 원본 과제와 안내는 `lessons/local-lab.js`에 있습니다. 사용자에게 SSH 서버를 제공하거나 접속·권한·셸 왕복 수행 여부를 자동 인증하지 않습니다. SSH 단계는 허용된 연습 서버가 있을 때 실행합니다.

검증은 `node scripts/advanced.mjs`, `node scripts/local.mjs`, `node scripts/local-native.mjs`로 수행합니다. 마지막 스크립트는 실제 설치된 Vim/Bash를 사용하며 Windows에서는 Git에 포함된 실행 파일을 기본으로 찾습니다. `VIM_BIN`, `BASH_BIN`으로 경로를 바꿀 수 있습니다. 실제 편집·매크로·외부 sort·검사기·readonly 오류·saveas 복구를 실행하지만 대화형 job control과 SSH 접속은 자동 테스트하지 않습니다.

설명은 [Vim의 반복 편집](https://vimhelp.org/usr_10.txt.html), [이동](https://vimhelp.org/motion.txt.html), [quickfix](https://vimhelp.org/quickfix.txt.html), [여러 파일 편집](https://vimhelp.org/usr_26.txt.html), [셸 왕복](https://vimhelp.org/usr_21.txt.html), [OpenSSH](https://man.openbsd.org/ssh.1)을 참고하고 내장 Vim에서 직접 확인합니다.

M6 **범위를 정하고 확인하며 치환하기**는 `#substitution`에서 시작합니다. 첫 명령은 콜론·s·구분자·찾을 문자열·새 문자열로 나눠 입력합니다. 현재 줄의 첫 항목, g를 붙인 현재 줄 전체, 1,2 줄 범위, % 전체 줄 범위, c 확인 옵션을 31단계에서 비교합니다. 실제 치환 확인 모드와 커서·내용을 검증하며 y·n 응답도 한 번씩 실행합니다. 이해 확인 3문제와 설명 줄을 보존하는 독립 과제가 이어집니다. 완료·복습 기록을 저장하지 않습니다. `node scripts/substitution.mjs`로 잘못된 명령 차단, 범위, y/n/q, 저장과 화면을 검증합니다. 치환 설명은 [Vim 사용자 매뉴얼](https://vimhelp.org/usr_10.txt.html)과 실제 내장 Vim의 실행 결과를 기준으로 합니다.

M6의 첫 안내 단원 **한 번 바꾸고, 점으로 반복하기**는 `#dot`에서 시작합니다. 검색, 단어 변경, 다음 결과로 이동, 점 반복, undo/redo, 저장을 18단계로 나누며 실제 Vim의 내용·모드·커서 위치를 확인합니다. 이해 확인 3문제 뒤에는 설명 문장에 있는 검색 결과를 건너뛰고 다른 항목만 변경하는 독립 과제가 이어집니다. M3 → 점 명령 → 검색과 치환 → 레지스터부터 이어지는 숙련 과정 → 로컬 실습으로 연결됩니다. 이 단원은 파일·완료·복습 기록을 브라우저에 남기지 않으며 재방문하면 처음부터 시작합니다. `node scripts/dot.mjs`로 반복 범위, 오답 차단, 저장, 기록 미생성, 화면 크기와 수업 전환을 검증합니다.

M5 **나의 Vim 작업 공간**은 `#workspace`에서 시작합니다. 새 버퍼 열기, 파일 전환, `:w`·`:wa` 저장, 저장본 다운로드, 삭제, 새로고침 복원을 지원합니다. 실제 Vim의 버퍼 번호·창 수·현재 창 번호와 미저장 상태를 표시합니다. **키 안내**에서는 파일 열기, 창 분할·이동·닫기, 새 파일 저장을 한 동작씩 설명합니다. 작업 공간은 학습 목록에서 언제든 열 수 있고 로컬 과정의 마지막 버튼으로도 연결됩니다. M5는 학습 횟수나 복습 일정을 기록하지 않습니다.

지원 범위는 `/work` 바로 아래의 텍스트 파일이며, 이름은 영문·숫자로 시작하는 영문·숫자·점·밑줄·하이픈 64자까지입니다. 하위 폴더, 바이너리, 기기의 실제 파일 접근은 지원하지 않습니다. 다운로드는 마지막 Vim 저장본입니다. 삭제는 확인 후 수행하며 미저장 버퍼는 먼저 저장해야 합니다. 직접 파일을 지우는 Vim 스크립트 대신 목록의 삭제 버튼을 사용하세요.

`vim-field-guide:workspace:v1`에 파일들을 보관하며 기존 미션·단원·복습 데이터와 분리합니다. 전체·범위·다른 이름·추가 저장 이벤트에서 실제 파일을 읽으므로 마지막 줄바꿈도 보존합니다. 저장 용량 부족 시 세션 내용은 유지하고 브라우저 저장 재시도·다운로드를 제공합니다. 같은 작업 공간을 여러 탭에서 동시에 편집하면 충돌할 수 있으므로 한 탭에서 사용하세요.

파일 이름과 저장 검증은 `lib/workspace-files.js`, Vim 연결은 `lib/workspace-vimrc.js`와 엔진 어댑터, 화면은 `WorkspaceSession`과 `WorkspaceGuide`에 둡니다. `node scripts/workspace.mjs`는 실제 Vim의 파일 생성·버퍼 전환·창 분할·숨은 버퍼 저장·범위 저장·다운로드·삭제·복원·저장 실패 처리와 모바일 레이아웃을 검증합니다.

M4 **다시 꺼내 쓰는 연습**은 `#review`에서 시작합니다. 입력·저장, 단어 하나 변경, 따옴표 안쪽 변경의 세 항목에 각각 세 가지 예제를 제공합니다. 학습 목록에서 선택할 수 있습니다. 해결 키 순서는 강제하지 않고 내용과 저장 상태를 검사합니다.

M2·M3·복습 화면의 **현재 상태 점검**은 요청 후 도착한 Vim 상태로 모드, 첫 불일치 줄, 명령줄, 검색 위치, 레지스터, 저장 여부를 구분합니다. 입력 도중의 상태를 자동으로 오답 처리하지 않습니다. 비교 화면은 공백을 `·`, 탭을 `⇥`로 표시하며 수정 전 점검 결과에는 표시를 남깁니다.

복습 완료 시 도움말 사용 또는 실패한 점검이 있었다면 10분 뒤, 도움 없이 해결했다면 1일 → 3일 → 7일 간격으로 제안합니다. 예정일 전 연습은 기존 날짜를 미루지 않습니다. 완료할 때마다 다음 예제로 바뀌며 중도 종료는 기록하지 않습니다. `vim-field-guide:review:v1`에는 항목별 완료 횟수, 다음 날짜, 최근 도움 여부와 점검 분류만 보관합니다. 입력 내용과 키 기록은 복습 기록에 저장하지 않습니다. 날짜는 기기의 시계를 기준으로 하며, 브라우저 간 동기화·외부 알림은 없습니다.

복습 데이터는 `lessons/review.js`, 간격과 저장은 `lessons/review-progress.js`, 진단은 `lessons/feedback.js`에서 관리합니다. `node scripts/review.mjs`로 실제 Vim 피드백, 다른 해결 방식, 예제 순환, 기록 복원, 복습 우선순위, 미저장 경고와 화면 크기를 검증합니다.

M3 **편집 명령을 문장처럼 조합하기**는 `#grammar`에서 시작합니다. 검색줄 열기부터 검색어·확정, c → i → w, y → i → 큰따옴표, d → i → 큰따옴표, P와 저장을 18단계로 나눕니다. 실제 커서 위치·모드·복사 내용·파일을 확인합니다. 이해 확인 3문제와 다른 문자열을 스스로 바꾸는 과제가 이어집니다. M2 완료 화면에서도 이 단원으로 이동할 수 있습니다.

단계별 수업은 `GuidedLesson`을 공유하고, 내용은 `lessons/`의 단원별 파일, 채점은 `lessons/evaluate.js`에 둡니다. 완료·저장 기록은 단원별 `vim-field-guide:<id>:v1` 키에 보관하며 기존 M2 기록은 유지됩니다. `node scripts/grammar.mjs`로 실제 Vim 전체 흐름을 검증합니다.

목표는 키 암기가 아니라 의도를 편집 연산으로 표현하는 능력입니다. 미션 해결 → 힌트와 비교 → 다른 방식으로 재도전 → 로컬 터미널에서 재현의 순환을 권장합니다. 타수는 관찰값이고 점수·통과 기준이 아닙니다.

1. 생존: 모드, 저장, undo/redo, 도움말. 첫 미션에 최소 안내를 제공합니다.
2. 편집 문법: operator + motion/text object, 검색으로 목적지 찾기.
3. 반복 제거: dot, 범위 치환, 매크로와 레지스터.
4. 작업 공간: 버퍼와 윈도 구분, split과 파일 간 편집.
5. 숙련 과정: marks/jumplist, 레지스터 보존, visual block, quickfix, arglist/argdo, global 명령의 안내와 독립 과제를 제공합니다. 변형 복습은 기존 입문·편집 문법의 세 항목만 지원합니다.
6. 로컬 전이 과정: `#local`에서 SSH, 권한, 외부 필터, 셸 왕복, 실제 파일 편집을 안내합니다. 브라우저의 가상 파일 성공을 실제 서버 작업 능력으로 동일시하지 않습니다.

## React 구조

- `src/App.jsx`: 미션 선택, 진행률, 화면 전환. 미션 이동은 전체 새로고침 없이 처리합니다.
- `src/components/`: 미션 목록·학습 세션·Vim 화면·설정 다이얼로그.
- `src/hooks/`: 저장 상태와 엔진 생명주기를 React에 연결합니다.
- `src/lib/`: 저장 데이터 검증, 폰트 로딩, Vim 어댑터, vimrc 생성.
- `src/styles/`: 기본 타이포그래피와 컴포넌트별 CSS Modules. 자체 CSS에 `!important`를 사용하지 않습니다.
- `src/missions.js`: 미션 데이터·힌트·완료 조건. UI 프레임워크와 독립적입니다.

React StrictMode를 활성화합니다. 미션 변경과 초기화 시 기존 Worker·이벤트·Observer·콜백을 정리하고, 확대/축소나 힌트 변경 시에는 Vim 인스턴스를 유지합니다. 기존 localStorage 키와 형식은 유지합니다. 긴 Ex 명령은 엔진 통신 버퍼 제한을 피하도록 vimrc 함수로 정의하고 짧은 호출만 전송합니다.

개발 원칙과 검증 절차는 [CONTRIBUTING.md](./CONTRIBUTING.md)에 정리합니다.

## 한계

vim.wasm은 오래된 실험적 이식판입니다. 현재 Vim/Neovim 전체 호환을 보장하지 않습니다. `:!grep`, `system()` 등 실제 OS 프로세스를 실행할 수 없습니다. 자동 JS 대체 엔진은 넣지 않았으며, 지원되지 않는 브라우저는 실행 불가 사유를 표시합니다. 키보드가 있는 최신 데스크톱 Chromium을 우선 검증합니다. Canvas 기반 편집기는 스크린리더 지원이 제한됩니다. Ctrl+Shift+F로 편집기에서 결과 확인 버튼으로 포커스를 옮길 수 있습니다.

## 검증

`npm test`는 초기값 실패, 정답 통과, 주변 내용 손상, CRLF, 누락 파일, 두 파일의 동시 수정 조건을 검사합니다.

로컬 Edge가 설치된 환경에서 실제 Vim 통합 검증:

```powershell
$env:TEST_URL='http://127.0.0.1:5173/vim-study/'
node scripts/smoke.mjs
```

다른 Chromium 채널은 `BROWSER_CHANNEL=chrome` 등으로 선택합니다. 여섯 미션을 실제 키 입력으로 풀고, 저장·새로고침 복원·오답 검출·다중 버퍼·모바일 가로 넘침을 확인합니다. 캡처는 무시되는 `test-results/`에 저장됩니다.

`node scripts/layout.mjs`는 `TEST_URL` 또는 기본 로컬 5184 포트에서 320px 휴대폰부터 1920px 데스크톱까지 7가지 화면 크기로 안내문 크기, 가로 넘침, Vim 캔버스 크기, 확대·복원 및 설정 창의 크기를 검증합니다.

`node scripts/lifecycle.mjs`는 StrictMode 시작, 새로고침 없는 미션 전환, Worker 수, 미저장 이동 경고, 뒤로 가기, 종료와 재시작을 검증합니다. `npm run format:check`로 JSX/CSS 형식을 확인합니다.

`node scripts/basics.mjs`는 새 단원의 아홉 단계를 실제 Vim 입력으로 통과시키며, 잘못된 입력 차단, 모드 전환, undo/redo, 저장, 질문 오답 재시도, 독립 연습과 완료 기록을 검사합니다. 기존 미션 테스트는 `#port`, 새 단원은 `#basics`로 접근합니다.
